## 七、安全风险评估

### 7.1 高风险 🔴
| 问题 | 文件 | 行号 | 说明 |
|------|------|------|------|
| TLS 校验绕过 | rebuild.sh | 743-744 | `NODE_TLS_REJECT_UNAUTHORIZED=0` 供应链风险 |
| GIT_SSL_NO_VERIFY | rebuild.sh | 522 | `GIT_SSL_NO_VERIFY=1` 供应链风险 |
| 硬编码代理 | pi-source-build.sh | 34 | `http://127.0.0.1:10809` |

### 7.2 中风险 🟡
| 问题 | 文件 | 说明 |
|------|------|------|
| 硬编码路径 | pi-wrapper.sh | `node-v22.23.2-linux-x64` 平台特定 |
| 内联 Node.js | pi-wrapper.sh | 大量内联 JS 可能有注入风险 |
| rm -rf 使用 | 多个文件 | 需确保路径变量正确 |

### 7.3 低风险 🟢
| 问题 | 文件 | 说明 |
|------|------|------|
| 颜色转义 | 多个文件 | ANSI 转义码处理 |
| 临时文件 | golden-tasks.sh | 使用 mktemp 安全创建 |

### 7.4 安全建议
1. **TLS 绕过**: 添加更明确的警告，限制仅在可信网络使用
2. **硬编码路径**: 使用环境变量或动态探测
3. **权限收紧**: 将 777 权限改为 755
4. **输入验证**: 部分脚本缺少参数验证

## 八、代码质量问题汇总

### 8.1 需要修复的问题

1. **文件过大**
   - `pi-wrapper.sh` (1800+ 行) - 建议拆分
   - `rebuild.sh` (1100+ 行) - 建议拆分

2. **权限问题**
   - `rebuild.sh`, `pi-source-build.sh`, `pi-wrapper.sh` 权限为 777，应改为 755

3. **Python 文件操作**
   - `npm-missing-deps.py` 和 `doc-extract.py` 未使用 `with` 语句

4. **重复代码**
   - `ok/fail/warn/info` 函数和颜色常量在多处重复定义

### 8.2 建议改进的项目

1. **提取公共函数库**
   - 创建 `lib/common.sh` 包含公共函数和常量
   - 各脚本 source 该库

2. **参数验证增强**
   - `pi-rescue.sh` 添加输入验证
   - 部分脚本添加 `--help` 支持

3. **错误处理统一**
   - 统一使用 `set -uo pipefail` 而非 `set -e`
   - 添加 trap 处理异常退出

4. **类型注解**
   - Python 脚本添加类型注解
   - TypeScript 脚本启用严格模式
