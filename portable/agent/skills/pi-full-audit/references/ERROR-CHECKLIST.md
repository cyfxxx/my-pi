# 误报判别清单（实战沉淀）

遇到以下情况先定性，别直接报：

- **密钥扫描命中**：先 `git ls-files <file>` + `git check-ignore -v <file>`。`portable/agent/` 下被 gitignore 的本地配置（`auth.json`、`models.json`、`trust.json`、`pi-link-*.json`）是正常存在，**不是泄露**；只有被 git 跟踪的才算 HIGH。示例占位、测试夹具命中亦属噪音
- **扫描范围与预览不符**：`review.sh --all` 输出的"待审文件数"远小于扫描预览数时，先怀疑排除规则误伤（例如扫描根本身命中某个 `! -path` 规则），而非仓库真的没文件
- **运行时数据噪音**：`--all` 可能扫入 `portable/` 下的运行时数据，其中的文本命中 `rm -rf`/密钥等模式属噪音，跳过
- **glob 陷阱**：`for d in dir/*/node_modules` 只在**全部不匹配**时保留字面量；部分不匹配 = 静默漏检，不是报错
- **"没找到 X" ≠ "X 不存在"**：先 grep 确认是否在其它层实现（如脱敏在 `core/secrets.ts` 内、路径解析在 `core/config.ts` 内），不要凭单点搜索结果下结论
- **架构边界工具的"允许项"**：`npm run check` 允许 `import type ... from 'vendor/pi'`（编译后擦除）与 `core/config.ts` 的路径解析例外；命中这两类不是违规
- **运行时行为必须实测**：子进程超时语义、事件触发时机、文件锁行为等以实测为准，不凭注释/直觉/审查者的机制描述。scout 只做读码级核实并在报告中标注"未实测"项，需实测的验证由主会话（有 bash）或委派 worker 完成
- **审查建议的行号引用**：常与实际位置不符（偏差可达几十行）——行为成立但行号错不算误报，以 grep/sed 实际定位为准并在结论中纠正
- **审查者的机制描述**：不可轻信，追完整调用链核实（例如"抛错即永久泄漏"实际是异步 error 事件且已有处理）
- **设计当 bug**：代码注释自认的故意设计（写死工具集/磁盘兜底/非阻塞注入）按设计权衡报并注明，不按纯 bug
- **同类遗漏**：审查只报一处的，检查同模块第二处（同型参数校验、同型路径拼接、同型阈值判断）
- **修复建议可改进**：审查给的修复方案常非最优或带副作用，核实后给出更优方案
- **vendor/pi 的构建产物**：`vendor/pi/**/dist/` 是上游构建产物，不是本项目源码；审查范围只含本仓库跟踪的源码与 `patches/`
- **`portable/agent/` 白名单文件 vs 本地状态**：只有 `.gitignore` 白名单内的 4 个配置文件属入库共享，其余为运行时本地；把本地状态"未入库"报为问题属误报
- **计数/版本类漂移必须带口径**：报"文档写 N，实际 M"之前，先给出取值命令与口径并复算一次。实测踩过：`ls scripts/*.sh scripts/*.mjs | wc -l`=40 被报成"文档 42 个脚本是漂移"，而文档口径含 `scripts/*.py`（`.sh+.mjs+.py`=42，文档正确）；另一处"`STRUCTURE.md` 写 v0.99.1 需核对"实测与 `vendor/PINNED_COMMIT` 一致。计数口径要明确**扩展名集合、是否含共享库/非脚本文件、是否含测试**
- **"需核对"不是发现**：没有实测值的疑点不得进报告。要么给"文档值 vs 实测值 + 命令"三件套，要么不列；把"待核对"写进发现清单等于把核实工作推给读者
- **目录清单类文档的计数**：这类漂移多半来自硬编码数量（`custom/README` 的 `core/ 8 个文件` 漏了新增的两个文件，实测真漂移）。判定为真漂移后，修复建议应偏向"数量 + 生成命令"或只列文件名，而不是把数字从 8 改成 10（下个 PR 还会漂）
