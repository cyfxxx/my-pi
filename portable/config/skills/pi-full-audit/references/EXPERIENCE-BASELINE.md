# 经验基线（历次审计沉淀，逐次追加）

> 每次执行审计后把过程经验沉淀到本文件（标注日期+场景）。只保留可复用教训，不复述一次性事件。
> 新增条目格式：`- YYYY-MM-DD 场景：教训 + 处置`。

## 通用审计纪律

- **执行纪律必须写进流程正文**：仅靠"经验基线"沉淀的流程性铁律（如"长任务禁用管道 tail""判读测试结果先看收尾标记"）执行者不会主动检索——反复踩坑的教训要升格进 SKILL/WORKFLOW 对应步骤。
- **报告行号普遍漂移**：复核按内容定位，行号仅作提示；行号精度可作为审查者质量信号。
- **恐惧性传播链描述需核对熔断路径**：涉及"失败→重启→再失败"的循环类判断，先核对计数器/熔断逻辑再定级。
- **设计取舍 vs 缺陷的定性要给依据**：代码注释自认的故意设计按设计权衡报告，不盲改行为；复核判"真实"不等于应改码，终审要区分「真实缺陷」与「真实存在但属有意取舍」。
- **修复建议常非最优**：核实后给出比初审更优的方案（注意副作用）。
- **大文件读取显式给 limit**：read 默认单次行数有限，读已知大文件首读就给 `limit: 300`，避免多次读取。

## 复核与终审（必做）

- 初次审查必然含缺陷：行号错误、机制描述错误、设计当 bug、定级偏高、同类遗漏。复核子代理产出质量高，不可省；要求复核者显式指出实际位置。
- **文档类发现豁免子代理复核**：核实只需一条 grep 的，主会话直接定论。
- 复核报告尾部截断时按核实成本分流：一条 grep 可核实的 LOW/事实类条目由主会话补验；机制复杂条目才重委派。
- **worker 报告不可全信**：并行 worker 改同一仓库时会互相误指改动归属；抽查 diff 时以文件路径归属判断，不采信 worker 对非自身文件的观察。worker 现场修正可优于审计方案，对"合理化偏离"逐个判断而非要求逐字执行。
- **worker abort ≠ 工作未做**：批返回 abort 时先 `git status` 核对产物覆盖面（对照任务清单逐模块查），缺失模块重派补齐；甄别调试遗留文件。

## 编辑与工具

- **多 edit 整批原子失败**：一次 edit 调用里若某个 oldText 不匹配，**整批都不应用**——长中文块编辑前先读回文件、确认替换方向，误配不落盘。
- **同轮并行 edit+bash 执行顺序不保证**：验证性 grep 可能读到编辑前快照——改动验证放独立轮。
- **正则/多层转义类精确修改用独立 .mjs 脚本执行最可靠**，比多次 edit 稳。

## git 与并行会话

- **多实例/并行会话是常态而非异常**：修复前先 `git log --oneline -3 -- <热点文件>` 确认归属；不碰对方文件。
- **提交只 add 本次改动清单的显式路径**，绝不 `git add -A`；提交前查 `git status` 的 staged 区（此前 staged 的内容会被一并带入）。
- **diff 方向误判**：`-` 行 = HEAD 有工作区无 → 本机旧；`+` 行 = 工作区新增 → 本地新改动。判断前先 `git log --all -- <file>` 查最近提交，日期巧合不构成证据。
- **push 被拒后 `stash -u` 有副作用**：会把未跟踪目录一并收走；恢复用 `git show stash@{0}^3:<path>` 精确取回。
- **活进程持续追加的统计文件**在提交与推送间隙会再变脏 → 对该单文件 stash 即可。

## 测试与修复

- **命令一律重定向落盘并保留收尾标记**：`cmd > /tmp/x.log 2>&1; echo "EXIT=$?" >> /tmp/x.log`；判读前先确认收尾标记存在，缺失 = 进程被提前终止，分段补跑。
- **全绿 ≠ 当前仓库状态健康**：两次运行间并行改动可改变一切；回归结论必须标注运行时间点，跨时段比较前重跑。
- **测试继承宿主 env 的隐蔽污染**：涉及时间/mtime/env 的用例必须显式隔离相关环境变量（save/restore in finally）。
- **时间窗口过滤类实现**：测试注入数据一律用 `Date.now() - N*窗口` 动态生成，不写死历史时间戳。
- **fake timers 默认伪造 Date**：写 timing 相关断言先想 fake Date 有无参与。
- **模块级固化路径是反模式**：模块顶层 `const X = getDir()` 会在 import 时固化，测试的晚注入失效——路径/环境相关值改函数内动态读取。
- **追加测试到文件尾先看 describe 是否闭合**，否则 it() 落在顶层引用不到局部变量。
- **红测验证用 `git stash push -q -- <file>` 单文件回退法**：跑红确认捕获旧行为 → `stash pop`，不碰并行改动。
- **安全修复改输出格式会使测试断言失配**：先判实现 vs 测试谁对，行为变化同步更新断言。

## 文档一致性

- **数量口径多点漂移是高频过时模式**：功能数/技能数/补丁数等在多份文档重复——发现一处失真后 grep 全仓库同口径数字逐处清点。
- **失效跨文档引用**：删公共 API/环境变量时，grep 引用面应含所有 `.md` 与注释。
- **状态标记矛盾**：勾选框 `[x]` 语义必须与文字一致，"规划确认"与"已完成"不能共用 `[x]`。
- **文档审查分组法**：按对象分组并行（根文档 / 注入主文档 / 模块注释↔源码 / packs 索引），每组只报可证伪项。

## 仓库体积

- **GitHub API `size` 有缓存延迟**：重写后仍显示旧值，本地 `git count-objects -vH` 的 `size-pack` 才准。
- **pack 减幅可能小于被删 blob**：delta 重算吸收属正常。
- **`git filter-repo` 优于 `filter-branch`**：后者在长历史中可能进程死亡未完成；filter-repo 会自动移除 remote（防误推），需重加并清理备份目录。
- **大二进制不入库**：建包/测试产物 >1MB 的二进制应改用小文件或文本占位 + README 说明生成方法；永久驻留历史才需重写。
- **多环境同步仓库必须通知所有设备重新 clone/同步**，否则旧对象会被推回。
