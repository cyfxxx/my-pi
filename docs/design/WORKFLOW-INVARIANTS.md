# 关键工作流的不变量（前置 ⇒ 后置）

> 来源：Lean4Agent（arXiv:2606.06523）的 Layer 1 用**类型系统自动查"读写一致性"**（读了既非初参、
> 也非可达前驱产出的变量）。my-pi 没有工作流图，但有**等价的隐式不变量**散落在守门与场景测试里——
> 本文把它们**集中写下来**，并给每条标注**执行它的守门**与**坏样本演示状态**。
>
> **纪律（本文的写法约定）**：
> - **有自动守门**要具体到脚本/测试文件；**没有就写「无自动守门（靠纪律/人工）」——不许编。**
> - **坏样本必须真跑过**才写"已实测"，并附命令与**失败输出原文**；跑不动的写「未演示（原因）」。
> - 标注 **由谁跑的**（`2026-10-08 复核`＝本次；`本会话`＝更早已实证过）。

## 6. 本次实测得到的**关于守门本身**的发现

**（1）两个常规守门确实会红（顺带自证，2026-10-08 复核）**——它们是"守门本身可信"的证据：

- **`STRUCTURE.md` 脚本计数**：把 `# 54 个运维脚本` 改成 `53` ⇒ `check-conventions.sh` 红，
  原文 `❌ STRUCTURE.md 写的是 53 个运维脚本，实际 54 个（改了 scripts/ 记得同步）`。
- **文档链接**：往 `DECISIONS.md` 追加一行指向不存在文件的链接（链接目标写 `../NOWHERE-XYZ.md`）⇒ `check-doc-links.mjs` 红，
  原文 `❌ 发现 1 个失效文档链接：`。
- （两条都已逐字还原，`git status --short` 为空。）

**（2）一条"我以为会红、实际没红"的发现**

我原以为"往被索引的源文档里追加一行"就会让知识索引漂移、`gen-doc-index.mjs --check` 变红。
**实测：没红（输出 `✅ 知识索引与源文档一致`）。** 原因是索引只抓每个条目的
**标题 + 标题后首句 + 最多 4 个实测数字 + 最多 3 个证据**（见 `scripts/gen-doc-index.mjs`）——
**追加在条目末尾、且不改动这些字段的文本，不会改变生成结果**。

⇒ 这条守门的语义是"**索引与源文档在被索引的字段上一致**"，**不是**"源文档逐字节未变"。
要触发它必须改动被索引的字段（例如**新增一个 `##` 小节**、或改标题/首句/数字/证据）。
**这是坏样本设计里容易搞错的地方：坏样本必须真的踩中判据**——我的第一版坏样本就没踩中。

## 7. 明确**没有自动守门**的不变量（缺口清单）

| 不变量 | 为什么没有守门 |
|---|---|
| "工具面预算**不事后放宽**" | 它是**人的判断**（阈值改动需决策），只能靠 `DECISIONS` 与 `docs/CHANGES.jsonl` 的 rejected 记录约束 |
| "知识/台账的**写入判据**"（该记什么、不记什么） | 无程序化判据；靠 `docs/INDEX.md` + `docs/CHANGES.jsonl` 的可检索性间接约束 |
| "留出集**开发期不看结果**" | 纪律性约定（第 19/20 步默认跳过），无自动强制 |
| "**默认关闭**的东西不许悄悄打开" | 靠 `DEFAULT_OFF_FEATURES` 单测 + 评审，无独立守门 |
