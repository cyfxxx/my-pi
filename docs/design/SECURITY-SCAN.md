# 安全防护：实测能力与分层设计（2026-10-09）

> 需求：模型**下载文件、网络搜索、操作浏览器**时要有防护——哈希校验、杀毒、特征识别、防篡改等；
> **优先用开源/免费的第三方程序或服务**（自研杀毒不合理）。
>
> **本文先回答"本环境到底有什么"（实测），再设计**。没装的能力一律写"不可用"，**不假设它存在**。

## 一、本环境能力实测（2026-10-09）

| 能力 | 实测 | 结论 |
|---|---|---|
| `clamscan` / `clamdscan` / `freshclam`（ClamAV） | **未安装** | ✗ 本地杀毒**当前不可用** |
| `yara` | **未安装** | ✗ 规则扫描不可用 |
| `file`（libmagic） | **未安装** | ✗ 类型识别需自备极小签名表 |
| `gpg` / `minisign` / `cosign` | **未安装** | ✗ 签名校验不可用 |
| `bwrap` / `firejail`（沙箱） | **未安装** | ✗ 隔离执行不可用 |
| `sha256sum` | **/usr/bin/sha256sum** | ✓ **哈希层可用** |
| python3 | ✓（**含 `requests`**；`pickletools` 属标准库） | ✓ 可做 **pickle opcode 扫描**等 |
| node / npm | ✓ | ✓ 脚本层零依赖可用 |
| pip 安装新包 | **被 PEP 668 拦下**（需 venv 或 `--break-system-packages`） | ✗ 不能随手装；**方案应零依赖** |
| **`urlhaus.abuse.ch/downloads/text/`** | **200** 1.48s | ✓ **免费、无需 key** ⇒ 恶意 URL 黑名单**本地缓存**可行 |
| `openphish.com/feed.txt` | 302（重定向） | △ 需跟随重定向，未深测 |
| `mb-api.abuse.ch/api/v1/`（MalwareBazaar） | **401** | ✗ 需鉴权/key |
| `virustotal.com/api/v3/files/` | 404（端点需 key+路径） | ✗ 需 API key |

**一句话**：**这台机器上没有任何杀毒/签名/沙箱能力**，只有哈希、python、node 与一条免费的 URL 黑名单。
⇒ 设计必须**零依赖可跑**，把"需要安装才能更强"的部分做成**可选增强**，并在输出里**如实区分"干净"与"没查"**。

## 二、选定形态：**脚本（零依赖） + 技能（流程） + 未来钩子（默认只记录）**

| 形态 | 采用 | 理由 |
|---|---|---|
| **脚本** `scripts/security-scan.mjs` | **✓ 核心** | 把可用的检查做成**一条命令**：文件/URL 进来 → 分层检查 → 三态结论 + 结构化落盘 |
| **技能** `pi-download-safety` | **✓** | 触发词（下载/安装/解压/模型文件）+ **流程纪律**：先哈希、再类型、再扫描、**没查就说没查** |
| 钩子（`tool_result` 里出现下载动作后自动扫描） | △ **默认只记录** | my-pi 已有 `tool_result` 钩子先例；但**自动阻断＝改默认行为，需用户批准** |
| 新声明工具 | ✗ | 工具面余量仅 1159 B；安全扫描是"按需调用的工具"，走技能+脚本更合适 |

## 三、分层与顺序（**先便宜后昂贵、先确定后模糊**）

| 层 | 检查 | 现成方案 | 本环境 |
|---|---|---|---|
| **L0 完整性** | SHA-256 + 与官方校验和比对；下载目录**哈希清单**（防篡改：mtime/大小/哈希变更） | `sha256sum` / node `crypto` | **✓ 可做（零依赖）** |
| **L1 结构识别** | ① magic bytes 与扩展名不符（PNG/JPEG/ZIP/ELF/PE/Mach-O 极小签名表）② zip/tar **路径穿越**与**炸弹比率** ③ **pickle opcode 扫描**（反序列化 RCE 一类）④ safetensors 头部/长度自洽 | 自备小签名表；`python3 pickletools`（标准库） | **✓ 可做（零依赖）** |
| **L2 本地杀毒** | 全文件特征扫描 | **ClamAV**（开源）、**YARA** + 社区规则集 | ✗ **未安装** ⇒ 输出 `未扫描`，并给出安装建议 |
| **L3 在线信誉** | URL/域名黑名单比对；哈希查询 | **URLhaus feed（免费无 key）**；VirusTotal / MalwareBazaar（需 key） | URLhaus **✓**；另两个 ✗ 需用户提供 key |
| **L4 浏览器/搜索侧** | 导航前查 URL 声誉；短链还原；可疑 TLD / 明文凭据提示 | URLhaus + 本地规则 | **✓ 部分可做**（**不做**"能防钓鱼"的虚假承诺） |

**判据顺序**：L0/L1 **每次必跑**（零成本）→ L2/L3 **按需/按开关**（慢或需网络）→ 结论取**最严的那一层**，
但**必须标注哪些层没跑**。

## 四、策略（这几条是安全设计的要害）

1. **默认只记录、不阻断**（阻断＝改默认行为，需用户批准）；一律 **fail-open**（扫描器自身出错不得卡住主流程）。
2. **三态结论，绝不二值化**：`clean`（该查的都查了且没问题）/ `suspicious`（有具体命中）/ **`not-scanned`（能力缺失或未跑）**。
   **`not-scanned` 不得显示成"安全"**——这是"不要假装安全"的硬要求。
3. **结论落盘**（JSONL，append-only，**不进模型上下文**），只把**摘要**给模型；这样既不污染上下文，又留可追溯证据。
4. **不重复查询**：在线查询按 URL/哈希缓存（含 TTL），避免烧掉免费额度。
5. **不采集敏感内容**：只记录哈希、路径、大小、结论；**不把文件内容或会话正文写进日志**。

## 六、怎么验证（**含自证**，这是必须的）

1. **自证（恶意样本必须红）**：用业界标准测试串 **EICAR**
   （`X5O!P%@AP[4\PZX54(P^)7CC)7}$EICAR-STANDARD-ANTIVIRUS-TEST-FILE!$H+H*`，68 字节，公开的杀毒测试文件）
   写进临时文件 ⇒ `security-scan.mjs` 必须报 `suspicious` 并给出命中规则名。**没有这条自证，扫描器等于摆设。**
2. **结构性自证**：造一个 **zip 路径穿越**样本（条目名为 `../evil.txt`）⇒ 必须命中；造一个**扩展名与 magic 不符**的样本
   （如 `.png` 实际是 ELF）⇒ 必须命中。
3. **完整性自证**：`--manifest` 生成后改一个字节 ⇒ 校验必须报"变更"，且指出是哪个文件。
4. **诚实性自证**：在没有 ClamAV 的机器上，结论里**必须**出现 L2 的 `not-scanned`（**断言"不出现 clean 冒充"**）。

## 七、诚实的局限（写清，避免给人虚假安全感）

- **必然漏报**：L0/L1 是**结构性检查**，不是病毒特征库；**没有 ClamAV/YARA 就没有真正的"杀毒"**。
- **L1 的 pickle 扫描**只能覆盖"反序列化触发"这一类（`pickletools` 能列出 opcode 与全局引用）；**不是通用恶意代码检测**。
- **URLhaus 是已知恶意 URL 列表**，命中率高但**滞后**（新域名不在表里）⇒ 未命中**不等于安全**。
- **浏览器内 JS 行为、网页挂马**本方案**管不到**（除非有沙箱/EDR，而本环境没有）。
- 要真正提升，需要用户安装/授权：**ClamAV**（若该平台有包）、**YARA + 规则集**、**签名校验工具**、或提供
  VirusTotal API key。**在这些到位之前，方案的价值是"把能查的查掉、把没查的说清楚"。**
