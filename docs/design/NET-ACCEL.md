# 网络加速：实测选型与落点（2026-10-09）

> 需求：国内网络限制让"查资料 / 访问外部信息 / 下载文件"经常失败，**连 GitHub 也常失败**。
> 要求：整合公开镜像源与加速链接，**参考已有开源项目，不要从零开始**。
>
> **本文的每条结论都带实测**（命令、HTTP 码、耗时、时间）。**没测的一律不写"可用"。**

## 一、实测结果（2026-10-09，本环境）

```
curl -sS -o /dev/null -m 10 -w '%{http_code} %{time_total}s' <url>
```

| 目标 | 结果 | 结论 |
|---|---|---|
| `raw.githubusercontent.com/...`（**直连**） | **000** 0.00s | ✗ 不通 |
| **`cdn.jsdelivr.net/gh/<owner>/<repo>@<branch>/<path>`** | **200** 0.40s | **✓ 唯一稳定可用的 GitHub 通道** |
| `ghproxy.net/<github-url>` | **000** | ✗ 不通 |
| `gh-proxy.com/<github-url>` | **000** | ✗ 不通 |
| `hub.gitmirror.com/<github-url>` | **000** | ✗ 不通 |
| **`hf-mirror.com`** | **200** 0.48s | ✓ 可用（HuggingFace） |
| **`pypi.tuna.tsinghua.edu.cn/simple/`** | **200** 2.62s | ✓ 可用（pip） |
| **`registry.npmmirror.com`** | **200** 0.49s | ✓ 可用（npm） |
| **`goproxy.cn`** | **200** 0.48s | ✓ 可用（Go） |
| **`mirrors.aliyun.com`** | 301 0.22s | ✓ 可用（跟随重定向） |
| **`mirrors.ustc.edu.cn`** | **200** 0.16s | ✓ 可用（最快） |
| `arxiv.org/html/<id>v<N>` | 200（早前实测，全文含附录） | ✓ 可用 |

### 这张表最重要的信息：**"网上常见的 GitHub 加速清单"在这里几乎全是废的**

`ghproxy` 家族的三个域名**全部 000**。如果照抄一份流行清单写进技能，模型会**逐个去试、逐个失败**，
既烧回合又得出"网络不通"的错误结论。**可用集只有 jsDelivr 一家**（对 GitHub 文件级访问）。
⇒ 这正是"**每个来源都要实测**"的价值所在。

**能力边界（诚实）**：jsDelivr 只覆盖**仓库里的公开文件**（raw 等价物），**不覆盖** Release 二进制、
`git clone`、API、私有仓库；Release 资产与 clone 在本环境**目前没有已验证的通道**（需要另找或让用户提供）。

## 二、选定形态：**技能（知识）+ 一个探测脚本**，不新增声明工具

| 形态 | 是否采用 | 理由 |
|---|---|---|
| **技能** `pi-net-mirror` | **✓ 主形态** | 镜像表是**知识**不是能力；按需加载、**零声明面成本**（工具面只剩 1159 B）；镜像会腐烂 ⇒ 技能里写"**先探测再使用**"的流程，而不是死表 |
| **脚本** `scripts/net-mirror.mjs` | ✓ 辅助 | 把上表变成**可重跑的探测**（`--probe` 输出可用/不可用 + 耗时；`--rewrite <url>` 把 GitHub URL 改写成 jsDelivr），这样**镜像失效能被发现**而不是等模型撞墙 |
| 钩子（失败自动改写重试） | ✗ 暂不做 | 自动改写会**改变工具行为与输出**（改默认行为），且重试语义容易被误解；先让人/模型显式调用 |
| 新声明工具 | ✗ 不做 | 声明面余量 1159 B；且它是"小工具"不是"模型必须随时看得见的能力" |

**降级链（写进技能，按序尝试、每次只前进一步）**：
1. `raw.githubusercontent.com/...` 直连（**先试一次**，0.1s 级失败可接受；通了就不折腾）
2. **`cdn.jsdelivr.net/gh/<owner>/<repo>@<branch>/<path>`**（本环境实测唯一稳定）
3. `hf-mirror.com`（若目标是模型/数据集）
4. 包管理：pip→清华（或 USTC）、npm→npmmirror、Go→goproxy.cn、系统包→USTC/阿里云
5. **全失败**：**如实报告"本环境无可用通道"** + 给出建议（让用户提供文件/换网络），**不要假装下载成功**

**可维护性**：`scripts/net-mirror.mjs --probe` 一条命令重测全表并输出耗时 ⇒ 镜像失效当天就能发现；
函数库/Release 二进制这类**没有验证通道**的目标，技能里明确写"**无验证通道**"，避免模型空转。

## 三、落点文件清单

| 文件 | 作用 |
|---|---|
| `portable/agent/skills/pi-net-mirror/SKILL.md` | 技能：触发词 + 实测表 + **降级链** + "先探测再使用"纪律 |
| `scripts/net-mirror.mjs` | `--probe`（重测全表）/ `--rewrite <url>`（GitHub→jsDelivr）/ `--print`（等价于 GitHub URL 列表） |
| 本文 | 实测证据与决策留痕 |

**成本与风险**：脚本零依赖（node 内置 fetch/https）⇒ 无安装成本；风险是**镜像域名会变**（缓解：探测）
与"改写只适用于文件级 URL"（缓解：技能里写明边界，脚本对不适用形态**明确报错**而不是猜）。

**怎么验证**：① `node scripts/net-mirror.mjs --probe` 对每个域名断言"要么 200 要么明确记录失败"
（**不许把失败静默当成功**）；② 用一个真实 GitHub 文件跑 `--rewrite` 后 `curl` 取回并比对 sha256
（端到端证明改写真的可用）；③ 脚本对 `releases/download/...` 这类**不适用**的 URL 必须**退出非 0**。
