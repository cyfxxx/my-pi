# 外部网页资源索引

本目录是**外部网页资源的检索索引** —— 与 `docs/` 下其它文档的区别是：那些讲的是 my-pi 自身，
这里记的是**外部可用的网站/工具**，用于平时查资料时先定位再访问。

| 文件 | 内容 |
|---|---|
| [`WEB-INDEX.md`](WEB-INDEX.md) | 人读版：按 13 个分类分节的表格（子类 + 标题 + 网址 + 说明位） |
| `web-index.json` | 机器可读版：`{category, sub, title, url, desc}`，便于 `jq` 过滤或程序消费 |

## 用法

```bash
# 按关键词找（标题 / 分类 / URL 都能命中）
grep -i '关键词' docs/reference/WEB-INDEX.md

# 只看已经写过说明的条目
grep -n 'desc: .\+' docs/reference/WEB-INDEX.md

# 只要 URL
grep -oE 'https?://[^ )>]+' docs/reference/WEB-INDEX.md | sort -u

# 按分类看（需要 jq）
jq -r '.entries[] | select(.category=="安全与取证") | "\(.title)\t\(.url)"' docs/reference/web-index.json
```

## 两条使用须知

1. **很多条需要外部网络才能访问 —— 打不开不等于失效。**
   索引来源是个人书签，其中相当一部分站点在受限网络下不可达。
   访问失败时先确认网络环境，不要据此断定网站已关停。
2. **这是索引，不是镜像。** 只记网址与标题，不抓取、不缓存页面内容。

## 关于说明信息（逐步补充）

本索引只记**网址与标题**，不含页面内容 —— 能"找到"但不足以便捷地"知道它是什么"。
为此每条预留了说明位（md 里的注释 `<!-- desc: -->`、json 里的 `desc` 字段），
**在使用过程中逐步补充**：

- **只补真正常用的那些** —— 不必逐条补齐，这份索引的价值就在"常用条目有说明"。
- **只在真的用过之后才写**，不要凭 URL 猜内容。
- 补写约定（写什么、踩坑怎么写、如何指向替代品）见
  [`WEB-INDEX.md`](WEB-INDEX.md) 顶部「关于说明信息」。

## 隐私纪律（重要）

本索引由**个人书签导出**过滤而来，过滤规则与理由如下 —— **将来更新索引时必须沿用同一套规则**，
否则会把个人数据带进公开仓库：

| 剔除项 | 为什么 |
|---|---|
| 个人账号 / 邮箱 / 网盘链接 | URL 内常含账号 ID、会话 ID（如 `?sid=`、`?uid=`），本身就是凭据泄漏 |
| 内网与本机地址（`192.168.*`、`127.0.0.1`、`10.*`） | 暴露私有网络拓扑 |
| 个人信息标识（用户名、邮箱前缀、账号 ID） | 直接指向本人 |
| 个人事务（政务、个人服务入口） | 非公共资源 |
| 个人域名/关键词搜索 URL | 把**你的搜索行为**一起带出去 |
| 浏览器内部页（`chrome://` 等） | 无意义 |
| URL 跟踪参数（`utm_*`、`_ga`、`_gl`、`spm`、`ref` …） | 既泄漏来源，也常把用户的搜索词一起带出去 |

> 实测教训：曾有一处 `namecheap.com/…?domain=<用户名>&_ga=…` 同时泄漏了用户名与搜索行为 ——
> 只按"文件夹名"过滤会漏，**必须同时按域名黑名单 + 参数剥离**，且生成后要跑一次泄漏复检。

### 内容取舍 vs 隐私过滤（两者独立，不要混）

上面那张表是**隐私过滤**：剔除的是"指向本人"的数据，与内容是否敏感无关。

另有四个分类属**内容取舍**，按用户要求**保留**在本索引里（`WEB-INDEX.md` 中标 ⚠️）：

| 分类 | 说明 |
|---|---|
| 网络代理与翻墙 | 代理/机场/翻墙工具与教程 |
| 接码与临时身份 | 临时邮箱、接码平台、身份信息生成 |
| 破解与账号交易 | 破解软件站、游戏账号交易平台 |
| 成人内容 | 成人向站点 |

这些是用户的收藏，保留与否由使用者判断；**保留它们不等于放宽隐私过滤** ——
改一类不得影响另一类。

## 更新方式

索引是从书签导出文件一次性生成的（生成脚本未入库，属一次性工具）。
若要更新，请重新执行同一套过滤规则，并在提交前对产出做一次泄漏扫描（见上表逐项检查）。
