# 失败模式：**RPC 的 prompt 被拒、父侧却当成功**

**来源**：`docs/BUG-REPLAYS.md` 第 26 条（使用层面故障台账，代码检查全绿但用起来才炸）。

**是什么**
**RPC 的 prompt 被拒、父侧却当成功**

**根因（WHY）**
缺 `streamingBehavior:'steer'` 时子进程直接拒绝 （`success:false`），而父侧对 `success:false` **照常 resolve** ⇒ 日志写「已投递（将在下一个 turn 边界执行）」并 `markConsumed` ✗ ⇒ 注入从未入队、行为不变 —— 典型「假装成功」

**确切命令序列**（复现/回归都靠它）
```bash
`bash -c 'MY_PI_NO_SUPERVISOR=1 PI_RPC_TRACE=1 ./my-pi.sh --no-skills --no-session -p "<4 轮 sleep+echo 任务>"'`，运行中再 `node scripts/subagent-inbox.mjs post worker#1 "追加指令：完成后 echo INBOX-OK >> /tmp/inbox-proof.txt"`
```

**怎么发现它（指纹）**
帧证据：`dir=in {"success":false,"error":"Agent is already processing. Specify streamingBehavior ('steer' or 'followUp')…"}`；而 `turns` 未增、`writeTools []`

**含确切语法的解法**
**已修 + 由真实 E2E 挡住**：修复后帧出现 `disposition:"queued"` + 注入后 **5 次 `turn_start`**，且 `/tmp/inbox-proof.txt` = `INBOX-OK` ✓
