# 失败模式：**创建/切换会话打断在跑的那一轮**

**来源**：`docs/BUG-REPLAYS.md` 第 38 条（使用层面故障台账，代码检查全绿但用起来才炸）。

**是什么**
**创建/切换会话打断在跑的那一轮**

**根因（WHY）**
TUI 里 `/new`（新建会话）或 `/resume`（会话选择器）会把当前会话**正在跑的那一轮直接中止** —— 用户视角是「我刚让它做的事被打断、结果丢了」。**根因在 pi 内部**（不是 my-pi 缺陷）：会话替换的三条入口 `newSession`/`switchSession`/`importFromJsonl` 都先走 `teardownCurrent()` → `await this.session.abort()`（`vendor/pi/packages/coding-agent/src/core/agent-session-runtime.ts:167-177`，调用点 `:212`/`:245`/`:299`/`:391`）⇒ 上游把「切换会话」与「打断在跑的一轮」实现成了同一个动作。2026-10-11 的活体实验已量出该签名（切换瞬间 pane 出现 `Operation aborted`、旧会话末条是 `content: []` 的 assistant、PID 不变=进程内替换），但当时只到「探明机制」为止

**确切命令序列**（复现/回归都靠它）
```bash
`PI_SCENARIO_KEEP=1 node scripts/test-scenario-session-switch.mjs`（真 pty + 真 supervisor + 真 pi + 假 provider，**18 项**）；单测 `npx vitest run custom/features/mode/__tests__/session-switch-guard.test.ts`（**20 项**）；**对照实验（改前必红）** `PI_SESSION_SWITCH_GUARD=off node scripts/test-scenario-session-switch.mjs`（应得 13/18）
```

**怎么发现它（指纹）**
切换前 pane 有工作指示器；切换后**旧会话文件末条是 `stopReason=aborted` / 空 content 的 assistant 记录**；同一轮本该落盘的回复**永远不再出现**在旧会话文件里；PID 不变（不是重启）

**含确切语法的解法**
`mode` 功能的 `session_before_switch` 守卫（`custom/features/mode/session-switch-guard.ts`）：忙碌时**等到回合结束再放行** ⇒ pi 的 `abort()` 打不到任何东西，切换仍由 pi 自己走完；等待非阻塞（editor 的 `onSubmit` 不被 await ⇒ **Esc 仍可立刻中断并切换**）；超预算只取消切换、**绝不**替用户中断回合；无 UI 一路放行；守卫异常 fail-open；`PI_SESSION_SWITCH_GUARD=off` 恢复上游行为
