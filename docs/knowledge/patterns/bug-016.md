# 失败模式：**终端层"假卡死"

**来源**：`docs/BUG-REPLAYS.md` 第 16 条（使用层面故障台账，代码检查全绿但用起来才炸）。

**是什么**
**终端层"假卡死"

**根因（WHY）**
agent 正常、用户却完全无法交互**：pi 进程健康（事件循环响应、整屏重绘正常、回合已干净收尾），但 14:25:27 之后再没有任何输入到达进程，用户视角就是"卡死"。根因在**终端/输入层**（该 pty 的主端在 Android 侧，`/proc` 里无持有者；当时内存吃紧 swap 4.4G/5.6G），不在 agent 层

**确切命令序列**（复现/回归都靠它）
```bash
`bash -c 'P=$(pgrep -x pi); awk "/^wchar/{print $2}" /proc/$P/io; kill -WINCH $P; sleep 2; awk "/^wchar/{print $2}" /proc/$P/io; grep -c socket /proc/$P/fd'`（wchar 增长 + socket=0 → TUI 活着，卡的是终端/输入层）；输入侧核对：`bash -c 'grep -o "lastActiveAt[^,]*" /root/my-pi/portable/agent/pi-link-active.json'` 与 `date +%s%3N` 比
```

**怎么发现它（指纹）**
① 0 CPU / 20s 内 0 输出、无 socket、无子进程；② `kill -WINCH` 后 `wchar` 有增长、`stty rows` 触发整屏重绘（数千字节）→ 事件循环活着；③ 回合**已收尾**：`aborted` 消息后毫秒级写入 `pi-link-state.json` 的 `status:idle`（= `agent_settled` 触发过）；④ `pi-link-active.json` 的 `lastActiveAt` 停在最后一条输入，之后无更新

**含确切语法的解法**
**不做自动重启**（按 2026-10-07 定的口径）：supervisor 只在 crash/admin action 时重拉，这类"终端层卡死"的处置是**关掉该 my-pi 所在的终端会话**再重开——不引入看门狗误伤在飞会话
