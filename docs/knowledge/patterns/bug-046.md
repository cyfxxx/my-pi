# 失败模式：**插件入口改成 `async apply` ⇒ 工具在全局工具面全缺席**（本次实现 DR-2 时引入的回归）

**来源**：`docs/BUG-REPLAYS.md` 第 46 条（使用层面故障台账，代码检查全绿但用起来才炸）。

**是什么**
**插件入口改成 `async apply` ⇒ 工具在全局工具面全缺席**（本次实现 DR-2 时引入的回归）

**根因（WHY）**
为了动态 `import` 宿主工具包，把 `dsh/plugin/entry.ts` 的 `apply` 改成 `async`，结果**经 cordis 装载**后 `tools.schemas()` 返回 **0 个**（facade 自己的汇总仍说 54），而直接 `await apply(ctx)` 又正常 54

**确切命令序列**（复现/回归都靠它）
```bash
`bash scripts/dsh-spike.sh`（A19 就是这条的守门）；复现：把 `apply` 改回 `async` 再跑 spike
```

**怎么发现它（指纹）**
spike **A19** 立刻变红：`注册 0 个工具；admin_get_config.type=undefined`（此前 54）；对照实验：`cordis 装载 ⇒ 0`、`直接 await apply ⇒ 54`

**含确切语法的解法**
**已修**：`apply` 恢复同步；宿主的 `dsh-tool-subagent` 模块改在**模块加载期**用顶层 `await` + `try/catch` 取好（取不到 = null，打开具名 agent 开关时逐条报失败，不影响其余能力）。结节见 `docs/design/CODING-TRAPS.md` #19
