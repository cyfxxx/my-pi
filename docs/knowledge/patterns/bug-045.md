# 失败模式：**"记录被否提案"的机制实际不生效**

**来源**：`docs/BUG-REPLAYS.md` 第 45 条（使用层面故障台账，代码检查全绿但用起来才炸）。

**是什么**
**"记录被否提案"的机制实际不生效**

**根因（WHY）**
`record-change.mjs --reject` 把条目**追加进 `docs/CHANGES.jsonl`**，而那个文件是**派生物** —— `gen-changes-ledger.mjs` 会用 `git log + DECISIONS.md` 把它**整个重新生成**（rejected 是从 `DECISIONS.md` 按标题标记抽取的）⇒ 手写的记录在下一次重建时**静默消失**。最毒的是它**打印"✓ 已记录"**，而且约定守门在台账漂移时会**提示你去跑 `--update`** —— 那正是抹掉记录的那一步

**确切命令序列**（复现/回归都靠它）
```bash
复现：`node scripts/record-change.mjs --reject "探测" --reason "探测用" && node scripts/gen-changes-ledger.mjs --check; node scripts/gen-changes-ledger.mjs --update; grep -c "探测" docs/CHANGES.jsonl`（修前：check 报漂移、update 后 0）；修后同一串命令 ⇒ `--reject` 自己就重建台账并**自检**该条已在 `CHANGES.jsonl` 的 rejected 里
```

**怎么发现它（指纹）**
实测三步（2026-10-16）：① `--reject "探测…"` ⇒ rejected 行数 **7 → 8**；② `gen-changes-ledger --check` ⇒ **❌ 已漂移**（因为重建集合里没有这条手写记录）；③ 按提示 `--update` ⇒ 回到 **7** 行，探测条目 **0 命中** ⇒ 记录没了

**含确切语法的解法**
**已修（2026-10-16）**：`--reject` 改为按抽取器认得的格式**追加到 `DECISIONS.md`（事实来源）**，随后自动跑 `gen-changes-ledger --update`，并**自检**这条真的进了台账（进不去就 exit 1 并给原因，不许"打印成功、实际没记上"）。顺带把"理由"里重复的"不采用："前缀去掉、同时保证理由行仍含标记词。本次据此**耐久地**登记了 8 条被否提案（`pnpm.overrides` 别名方案、写死让位名单、`mypi_subagent` 改名、plan 直接让位、诊断报"入桶 yes/no"、箭头函数 fake、`ln -sfn` 整目录软链、vendored packs 一并改名）。结节见 `docs/design/CODING-TRAPS.md` #16
