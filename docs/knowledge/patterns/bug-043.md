# 失败模式：**打包形态冒烟自 2026-10-18 起静默失效**（连带暴露 `ln -sfn` 的目录语义坑）

**来源**：`docs/BUG-REPLAYS.md` 第 43 条（使用层面故障台账，代码检查全绿但用起来才炸）。

**是什么**
**打包形态冒烟自 2026-10-18 起静默失效**（连带暴露 `ln -sfn` 的目录语义坑）

**根因（WHY）**
`dsh-package.sh` 把 tgz 装到**独立目录**再从那里加载，而 `entry.ts` 那天为 `defineTool` 编译新增了宿主 import `@deepseek-ai/dsh-tools` ⇒ 独立目录里没有宿主包，脚本开始以 `ERR_MODULE_NOT_FOUND: @deepseek-ai/dsh-tools` 失败。它**不在任何自动门禁里**（重、要装包），所以从当天到被发现一直是坏的 —— 典型的"没跑过的守门等于没有守门"。修的过程中又撞上第二个坑：`npm install` 因 peerDependency 先建了**真目录** `node_modules/@deepseek-ai/`，而 `ln -sfn "$SRC" "$D/node_modules/@deepseek-ai"` 会把链接建到**目录里面**（`@deepseek-ai/@deepseek-ai → SRC`）⇒ 症状是"补了宿主包还是找不到"

**确切命令序列**（复现/回归都靠它）
```bash
`bash scripts/dsh-package.sh`（修后应从"已安装位置"加载出 **54 工具 / 0 特性失败**）；`node dsh/spike/smoke-built.mjs`（每次构建都跑的自包含断言）
```

**怎么发现它（指纹）**
失败栈：`Cannot find package '@deepseek-ai/dsh-tools' imported from /tmp/my-pi-plugin-install/node_modules/my-pi-dsh-plugin/dist/my-pi-plugin.mjs`；补链后仍失败时 `ls -la node_modules/@deepseek-ai/` 可见嵌套的 `@deepseek-ai -> /root/my-pi/dsh/spike/node_modules/@deepseek-ai`

**含确切语法的解法**
**已修**：宿主包**逐包**补链接（跳过已存在项，与 `dsh-build.sh` 同做法）；并把"产物不得含 `@earendil-works/*` import"的**零成本断言**加进构建冒烟（`smoke-built.mjs`）⇒ 自包含性从此每次构建都被检查（灵敏度已验：不带 `--alias` 构建时该断言命中 3 处）。结节见 `docs/design/CODING-TRAPS.md` #14
