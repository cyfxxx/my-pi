# 失败模式：**守门把「读不了仓库」误报成「有未提交的修改」，方向完全相反**

**来源**：`docs/BUG-REPLAYS.md` 第 30 条（使用层面故障台账，代码检查全绿但用起来才炸）。

**是什么**
**守门把「读不了仓库」误报成「有未提交的修改」，方向完全相反**

**根因（WHY）**
`check-isolation.sh` 检查 6 用 `if ! git diff --quiet 2>/dev/null` 判 `vendor/pi` 是否干净。`git diff --quiet` 有**三个**结局——0 干净、1 有改动、**129 读不了仓库**（exFAT/网络盘上因 "dubious ownership" 退化为 `--no-index` 用法错误）。只看"非 0"就把 129 归进"有改动"，再加 `2>/dev/null` 吞掉线索 ⇒ 报出 `vendor/pi/ 有未提交的修改`，而它其实是干净的。同类写法在 `doctor.sh`、`sync-upstream.sh` 里各有一处（后者会因此拒绝同步）

**确切命令序列**（复现/回归都靠它）
```bash
`bash -c '. scripts/lib-vendor.sh; git_dirty_state vendor/pi; echo "state=$?"'`（0=干净／1=有改动／3=读不了；期望 0）；`bash scripts/check-isolation.sh`（应打印"vendor/pi/ 干净"）
```

**怎么发现它（指纹）**
报错说"有改动"，但 `git -C vendor/pi status --porcelain` 输出 **0 行**；`git -C vendor/pi diff --quiet; echo $?` 得 **129**（不是 1）；手动 `git config --global --add safe.directory <vendor/pi>` 后立刻变绿 ⇒ 证伪"有改动"

**含确切语法的解法**
**已修 + 判据收敛**：`scripts/lib-vendor.sh` 新增 `git_repo_readable` / `git_dirty_state`（三态）/ `git_unreadable_hint`，由 `check-isolation.sh`、`doctor.sh`、`sync-upstream.sh`、`build.sh` 共用（单一事实来源，防口径漂移）；`build.sh` 在 clone 后**自动登记** `vendor/pi` 的 `safe.directory`；详见 `docs/operations/BUILD-PORTABILITY.md` §4.1
