# 失败模式：**canvas 原生构建挡住整个构建**

**来源**：`docs/BUG-REPLAYS.md` 第 29 条（使用层面故障台账，代码检查全绿但用起来才炸）。

**是什么**
**canvas 原生构建挡住整个构建**

**根因（WHY）**
`vendor/pi/packages/ai` 的 `canvas@3.2.3` 是 **devDependency**（该包测试用），无预编译包时 npm 退化为 `node-gyp` 源码编译，而 canvas 需要 GTK/cairo ⇒ 构建在 `cairo.h: No such file or directory` 处整链失败；而它在 pi-ai 源码与测试里**零引用**、构建产物也不依赖它

**确切命令序列**（复现/回归都靠它）
```bash
`bash -c 'NPM_CONFIG_IGNORE_SCRIPTS=1 bash scripts/build.sh; echo exit=$?'`（应在无 GTK 的机器上构建成功）；引用核查：`bash -c 'grep -rn canvas vendor/pi/packages/ai/src vendor/pi/packages/ai/test'`（无输出 = 零引用，证明可安全跳过）
```

**怎么发现它（指纹）**
报错 `npm error path .../node_modules/canvas` + `command ... prebuild-install -r napi` + `cairo.h: No such file or directory`（前者失败后才回退 node-gyp rebuild）；旁边常伴随 `unable to get local issuer certificate`（Node 自带 CA 链问题，与 canvas 无关，别误判）

**含确切语法的解法**
**旁路用法已写进 build.sh 头部注释**（无自动守门：属"可选依赖缺平台构建工具"，刻意不做成失败）；上游 README 亦有前提 *"Pi does not require dependency lifecycle scripts"*；详见 `docs/operations/BUILD-PORTABILITY.md` §3
