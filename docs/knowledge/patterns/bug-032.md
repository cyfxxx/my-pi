# 失败模式：**VeraCrypt 挂载的卷在 `Get-Volume` 里看不见 ⇒ 盘符探测静默落空（还被 `$ErrorActionPreference='Stop'` 放大成整体中断）**

**来源**：`docs/BUG-REPLAYS.md` 第 32 条（使用层面故障台账，代码检查全绿但用起来才炸）。

**是什么**
**VeraCrypt 挂载的卷在 `Get-Volume` 里看不见 ⇒ 盘符探测静默落空（还被 `$ErrorActionPreference='Stop'` 放大成整体中断）**

**根因（WHY）**
给便携启动器写「遍历所有卷找仓库」的逻辑时，`Get-Volume` **不列出 VeraCrypt 挂载的卷**（实测漏掉 M:），却会列出 0 容量的幽灵卷（如 H:）⇒ 对幽灵卷 `Join-Path` 抛 `DriveNotFoundException`；若脚本开头设了 `$ErrorActionPreference='Stop'`，该异常会**终止整个探测循环**，于是从仓库外启动时报「找不到仓库」，从仓库内启动却正常（`$PSScriptRoot` 短路了探测）——**故障只在特定入口出现**，极易误判成脚本逻辑错

**确切命令序列**（复现/回归都靠它）
```bash
对比两个枚举器：`powershell -c "Get-Volume -EA 0 ｜ Select-Object DriveLetter"` 与 `powershell -c "Get-PSDrive -PSProvider FileSystem ｜ Select-Object Name"`；逐盘符安全探测：`powershell -c "foreach($L in 'C','D','E','G','H','M'){ try{ if(Test-Path -LiteralPath ($L + ':\my-pi\my-pi.sh') -EA Stop){ 'hit ' + $L } }catch{} }"`
```

**怎么发现它（指纹）**
实测：`Get-Volume` 列出的盘符不含 M:，而 `Test-Path M:\` 为 True、`Get-PSDrive -PSProvider FileSystem` 与 `[IO.DriveInfo]::GetDrives()` 均能看到 M:；同一脚本从仓库内启动成功、从工具分区启动报「未找到 my-pi 仓库」

**含确切语法的解法**
**已硬化**：`scripts/run-my-pi.ps1` 改为 `Get-PSDrive` 枚举 + 逐盘符 `Test-Path -LiteralPath` + `try/catch`，并**刻意不设** `$ErrorActionPreference='Stop'`（文件头注明原因）；找不到时给出「加密卷可能未挂载」的可操作提示而非静默失败；详见 `docs/operations/BUILD-PORTABILITY.md` §4.3
