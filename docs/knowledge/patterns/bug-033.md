# 失败模式：**台账表格被空行割裂 ⇒ 下游按行解析会静默漏条**

**来源**：`docs/BUG-REPLAYS.md` 第 33 条（使用层面故障台账，代码检查全绿但用起来才炸）。

**是什么**
**台账表格被空行割裂 ⇒ 下游按行解析会静默漏条**

**根因（WHY）**
`docs/BUG-REPLAYS.md` 的台账表在若干行之间插了空行（本文件 L53/L55 曾是），Markdown 渲染仍连成一张表，但**任何按「行以竖线开头」解析的工具都会把它当成多张表**——`knowledge-compile.mjs` 的 `readIncidents()` 正是这种逐行解析，漏掉的条目不会报错、只会静默少生成 pattern 页。属「格式看起来没问题、但机器读法与人眼读法不一致」的隐患

**确切命令序列**（复现/回归都靠它）
```bash
看空行落点：`grep -n '^$' docs/BUG-REPLAYS.md`；对比两个计数：`awk '/^｜/' docs/BUG-REPLAYS.md ｜ wc -l` 与 `grep -c '^｜ [0-9]' docs/BUG-REPLAYS.md`；端到端：`node scripts/knowledge-compile.mjs --check` 应仍绿
```

**怎么发现它（指纹）**
表格行数与台账实际条数不符；或台账里两条之间夹着空行；`node scripts/knowledge-compile.mjs --check` 通过**也不能证伪**（它只比对已解析到的条目与已有页面，漏解析的条目在两边同时缺席）

**含确切语法的解法**
**本次已修**（删除表格内 3 处空行，台账恢复为一张连续表）；**无自动守门**——建议后续给 `check-conventions.sh` 加一条「台账表体内不得出现空行」，否则同类割裂会再次静默漏条
