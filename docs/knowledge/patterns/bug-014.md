# 失败模式：**system 加固块静默丢失（进程内前缀漂移）**

**来源**：`docs/BUG-REPLAYS.md` 第 14 条（使用层面故障台账，代码检查全绿但用起来才炸）。

**是什么**
**system 加固块静默丢失（进程内前缀漂移）**

**根因（WHY）**
`before_agent_start` 处理器返回的 `systemPrompt` 没生效——pi 会**静默吞掉**该处理器的异常（只发给内存 listener，不落盘），于是 my-pi 追加的 772B system 加固块整块消失，请求退回"纯分段渲染"。system 在请求最前，少一块 = 前缀从第 0 个 token 起分叉 → **整段全价重放**。实测一次会话内 `system` 在 8020B/7239B 两变体间来回翻（14:11:22 翻过去、14:25:27 翻回来），两次 = 147,555 + 10,308 token = 该会话**全部未命中的 60.8%**

**确切命令序列**（复现/回归都靠它）
```bash
`npx vitest run custom/features/context/__tests__/system-prompt-total.test.ts`（让 `ctx.getContextUsage`/`pi.getActiveTools` 抛错，断言产出的 systemPrompt 仍与正常路径**逐字节相同**）；`npx vitest run custom/features/context/__tests__/prefix-fingerprint.test.ts -t '加固块'`；`node scripts/test-usage-metrics.mjs`（`加固块缺失=1` → alert，含"持续缺失无转换标记"用例）；真数据核对：`node -e "const l=require('fs').readFileSync('portable/memory/logs/prefix-fingerprints.jsonl','utf8').trim().split('\n').map(JSON.parse);console.log('加固块缺失',l.filter(r=>r.systemAppend===false).length,'/',l.length)"`
```

**怎么发现它（指纹）**
`portable/memory/logs/prefix-fingerprints.jsonl` 里**同一进程内**出现 `changed:["system",…,"messages@0-7"]` 且 `systemBytes` 差值 ≈ 772B；新字段 `systemAppend:false`（**逐条**判据，不是只看转换标记——进程首条 `prev=null` 时 `changed` 恒为空，"每轮都丢"反而一个标记都不产生）；独立台账 `portable/memory/logs/system-append-lost.jsonl`；`daily-health` 的 `加固块缺失=N` 字段

**含确切语法的解法**
① `before_agent_start` 改「关键路径 vs 可选增强」分层：拿 system 文本 + 追加加固块只做纯字符串运算，其余（工具分层/顺序对齐/用量校准/提示）全部就地 try/catch → 增强失败不再牵连前缀；② `prefix-fingerprint.ts` 记 `systemAppend` + `systemSections`/`systemChangedSections`（分段字节表，能区分"某段被改写"与"末尾整块丢了"）+ `system:append-lost`/`system:append-back` 标签；③ 独立台账 + 有 UI 时 `ui.notify`；④ `daily-health` 按**逐条** `systemAppend:false` 一律 alert（不再混进"疑似整段重算"）
