# 失败模式：**`local`/`declare` 同一行里引用刚声明的变量 ⇒ `set -u` 下失败，报错却指向变量名**

**来源**：`docs/BUG-REPLAYS.md` 第 42 条（使用层面故障台账，代码检查全绿但用起来才炸）。

**是什么**
**`local`/`declare` 同一行里引用刚声明的变量 ⇒ `set -u` 下失败，报错却指向变量名**

**根因（WHY）**
写 DSH 模式场景脚本时写成 `local label="$1" mode="$2" out="$LOG_DIR/run-$label.log"`，脚本跑到那里直接 `line 89: label: unbound variable` 退出 —— **看起来像"调用方没传参"，实际是 bash 语义**：`local` 的所有词**先展开**再赋值，同一行里 `$label` 展开时那个赋值还没生效

**确切命令序列**（复现/回归都靠它）
```bash
`bash -c 'set -u; f(){ local a="$1" b="x-$a"; echo "$b"; }; f one'`（❌ `a: unbound variable`）对照 `bash -c 'set -u; f(){ local a="$1"; local b="x-$a"; echo "$b"; }; f one'`（✓ `x-one`）
```

**怎么发现它（指纹）**
脚本输出只有那一条 unbound variable（第 89 行），函数第一行；同一函数改成多条 `local` 后立刻正常（场景随即跑通并给出 53/10 与 0/1 两组注册汇总）

**含确切语法的解法**
**无自动守门**（属 bash 写法约束；结节见 `docs/design/CODING-TRAPS.md` #13），已修 `scripts/dsh-scenario-mode.sh`
