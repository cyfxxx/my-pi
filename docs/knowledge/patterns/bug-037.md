# 失败模式：**[未解决 · 平台] supervisor 的实例身份用 bash `$$`，而 pi 报的是 Windows PID ⇒ admin 重启链路在 MSYS/Windows 上静默失效**

**来源**：`docs/BUG-REPLAYS.md` 第 37 条（使用层面故障台账，代码检查全绿但用起来才炸）。

**是什么**
**[未解决 · 平台] supervisor 的实例身份用 bash `$$`，而 pi 报的是 Windows PID ⇒ admin 重启链路在 MSYS/Windows 上静默失效**

**根因（WHY）**
`SUPERVISOR_OWNER_PID="${SUPERVISOR_OWNER_PID:-$$}"` 取 bash 的 PID，但 pi 写进请求的 `ownerPid` 是 **node 的 `process.ppid`** —— 在 Windows/MSYS 下那是 **Windows PID**，与 MSYS 自己的 PID 命名空间**永不相等**（实测 `$$`=1720 而 node 报 ppid=42248）。于是 supervisor 把**自家 pi** 写下的重启请求判为"别人的请求"而拒绝，主循环只跑一轮就退出**且不报错**。Linux 上两者同源，故一直没暴露

**确切命令序列**（复现/回归都靠它）
```bash
判据（三步）：`bash -c 'echo $$'` 与 `node -e 'process.stdout.write(String(process.ppid))'` 在同一 bash 里取值**不等**即复现；端到端见 `bash scripts/test-supervisor.sh` 的"主循环"段；测旧 node 无关
```

**怎么发现它（指纹）**
supervisor 测试 16 项失败中，起因为此的是：`主循环跑满两轮（期望 2，实际 1）`、`ownerPid = 本 supervisor（ppid 链路）→ 请求被认领并执行（期望 2，实际 1）`、`轮次记录：两轮 restart → exit（期望 restart,exit，实际 exit）`。现场取证：stub 已正确写 `action:restart` 且 `ownerPid=process.ppid`，但 `rounds.jsonl` 记 `adminAction:"" decision:"exit"`

**含确切语法的解法**
**未解决，已记录**。实测过的两种改法都会**引入回归**，故未采用：①把 `SUPERVISOR_OWNER_PID` 改成 node 报的真实 PID → 测试里 `ownerPid=$$` 的 3 个用例转红（19 项）；②在 `read_admin_action` 里**同时接受两套 PID**（`me ｜｜ me2`）→ 同样因测试用进程内 `$$` 而转红（19 项）。**正解需要连同测试一起改**：让 `test-supervisor.sh` 的 `mark_recovery_restart_log`/`write_state` 使用"子进程会看到的父 PID"，并统一 §5.2 提到的 `/tmp` 路径口径（MSYS 把 `/tmp` 映射为 `D:/Desktop/Tmp`，跨 node 传参会改写成 Windows 形式）。影响面：Windows 上 admin 重启/切会话不可用；Linux/Termux 不受影响
