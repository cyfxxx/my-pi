# 失败模式：**[已修 · 平台] supervisor 的实例身份用 bash `$$`，而 pi 报的是 Windows PID ⇒ admin 重启链路在 MSYS/Windows 上静默失效**

**来源**：`docs/BUG-REPLAYS.md` 第 37 条（使用层面故障台账，代码检查全绿但用起来才炸）。

**是什么**
**[已修 · 平台] supervisor 的实例身份用 bash `$$`，而 pi 报的是 Windows PID ⇒ admin 重启链路在 MSYS/Windows 上静默失效**

**根因（WHY）**
supervisor 以 `SUPERVISOR_OWNER_PID="${SUPERVISOR_OWNER_PID:-$$}"` 取身份，而 pi 写进请求的 `ownerPid` 取的是 **node 的 `process.ppid`**，注释假定"我的父进程就是拉起我的 supervisor"。这在 Linux 成立，但在 **Windows/MSYS 下不成立**：MSYS 每次启动 `.exe` 都新建一个**短命中间进程**，故 node 看到的父 PID **不是** bash/supervisor 的 PID（实测同一 bash 内三次调用分别得到 33600 / 22048 / 39220，且与 `$$`、`/proc/$$/winpid` 都不等）。后果：supervisor 把**自家 pi** 写下的重启请求判为"别人的请求"而拒绝，**主循环只跑一轮就退出且不报错** —— 用户视角是"切了模式/请求重启后进程直接没了"

**确切命令序列**（复现/回归都靠它）
```bash
三值对照即可复现：同一 bash 内 `$$`、`node -e process.stdout.write(String(process.ppid))`（命令替换）与直接跑该命令给出**三个互不相等**的值（实测 37112 / 45016 / 18176），再加上 `/proc/$$/winpid` 又是另一个值。端到端：`bash scripts/test-supervisor.sh` 的主循环段；或跑 `bash scripts/pi-supervisor.sh` 并观察 `portable/agent/recovery/rounds.jsonl` 只有一轮
```

**怎么发现它（指纹）**
supervisor 测试曾 16 项失败，其中 8 项即此：`主循环跑满两轮（期望 2，实际 1）`、`ownerPid = 本 supervisor（ppid 链路）→ 请求被认领并执行（期望 2，实际 1）`、`轮次记录：两轮 restart → exit（期望 restart,exit，实际 exit）`。现场取证：stub 已正确写 `action:restart` 且 `ownerPid=process.ppid`，但 `rounds.jsonl` 记 `adminAction:"" decision:"exit"`；插桩显示 `state.ownerPid=18176` 而 `SUPERVISOR_OWNER_PID=38424`

**含确切语法的解法**
**已修（2026-10-13）**。正解不是"让 supervisor 猜出自己的 Windows PID"（那不可行：`$(...)` 在 MSYS 下多一层 fork，PID 每次变），而是**父进程知道自己的身份、子进程用环境变量继承它** —— 与 PID 语义无关，跨平台一致：① `pi-supervisor.sh` export `MY_PI_SUPERVISOR_PID="${MY_PI_SUPERVISOR_PID:-$$}"` 并据此定 `SUPERVISOR_OWNER_PID`；② pi 侧 `autopilot/store/ops.ts` 写 `ownerPid` 时**优先取该环境变量**，读不到才回退 `process.ppid`（兼容旧启动方式）；③ `lib-mode.sh` 的 `mode_session_arg` 补 `[A-Za-z]:/*` 判据（原先只认 `/*`，**丢弃盘符路径**）；④ 测试侧统一路径形式：`modes.json` 由 `node -e` 读取，MSYS 形式 `/tmp/…` 拼进 `$ROOT/$AGENT_DIR` 会得 `/m/my-pi//tmp/…` ⇒ node **ENOENT** ⇒ `mode_resolve` 的 catch **无条件回落 full**（6 项会话模式断言全红的真因）。实测：supervisor 测试 **16 项失败 → 111 项全过**；`golden-tasks --fast` 全绿；对照实验：`ownerPid=process.ppid` → 只跑 1 轮，`ownerPid=$MY_PI_SUPERVISOR_PID` → 跑 2 轮且第二轮收到 `--session`，而写"别人的" ownerPid 仍只跑 1 轮（多实例隔离未被削弱）
