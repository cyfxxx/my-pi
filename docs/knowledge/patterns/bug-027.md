# 失败模式：**Node 主版本够、minor 不够 ⇒ 构建中途才崩**

**来源**：`docs/BUG-REPLAYS.md` 第 27 条（使用层面故障台账，代码检查全绿但用起来才炸）。

**是什么**
**Node 主版本够、minor 不够 ⇒ 构建中途才崩**

**根因（WHY）**
`package.json`、13 个 vendor 包与上游 README 都要求 Node **>= 22.19.0**，而 `build.sh` 与 `doctor.sh` 只比对**主版本**（`>= 22`）⇒ Node 22.14.0 被放行，直到上游脚本用 `node scripts/*.ts`（内置类型剥离，22.18+ 才默认开启）时才以 `ERR_UNKNOWN_FILE_EXTENSION` 失败，报错点离根因很远

**确切命令序列**（复现/回归都靠它）
```bash
`bash -c 'bash scripts/doctor.sh 2>&1'`（看第 [1] 节是否判"低于要求"）；端到端：`bash -c 'bash scripts/build.sh; echo exit=$?'` 应在第 1 步就拒绝，而不是构建中途才崩
```

**怎么发现它（指纹）**
报错 `TypeError [ERR_UNKNOWN_FILE_EXTENSION]: Unknown file extension ".ts" for .../packages/ai/scripts/check-model-data.ts`；`node -v` 显示 22.14.x（主版本同为 22 却失败）

**含确切语法的解法**
**已硬化**：`scripts/lib-vendor.sh` 的 `node_version_ok`（逐段比较 major/minor/patch）+ `node_version_hint`，由 `build.sh` 与 `doctor.sh` **共用**（单一事实来源，防两处口径漂移）；实测 22.14.0 被拒、22.23.3 构建全绿，详见 `docs/operations/BUILD-PORTABILITY.md` §1
