# 失败模式：**便携工具链用 `bash -l` ⇒ 换机器后核心命令全没了**

**来源**：`docs/BUG-REPLAYS.md` 第 31 条（使用层面故障台账，代码检查全绿但用起来才炸）。

**是什么**
**便携工具链用 `bash -l` ⇒ 换机器后核心命令全没了**

**根因（WHY）**
把 Git for Windows 复制到 U 盘做「盘内自带 bash」时，若以登录 shell 调用（`bash -lc` 或带 `-l`），便携 Git 的 `/etc/profile` 会注入**原安装机器的绝对路径**（如 `/d/App_X/Git/usr/bin`）⇒ 换到别的机器后 `dirname` / `mkdir` / `tail` 全部 `command not found`，`my-pi.sh` 第 7、16 行当场崩。**报错点离根因极远**：看起来像脚本有 bug，实为调用姿势问题。注意 `bash -c`（非登录）时 MSYS 会自行补 `/usr/bin`，核心工具正常可用——所以「本机能跑」不能证明「换机器也能跑」

**确切命令序列**（复现/回归都靠它）
```bash
`bash -c 'env -i SYSTEMROOT="C:\\WINDOWS" PATH="$RT/PortableGit/usr/bin:$RT/PortableGit/mingw64/bin:$RT/node" "$RT/PortableGit/bin/bash.exe" -c "cd $REPO && ./my-pi.sh --version"'`（`env -i` 清空环境变量，应仍打印 `1.0.4`）；正反断言：`bash -lc 'command -v dirname'`（登录态，新机器会失败）
```

**怎么发现它（指纹）**
同一份便携 Git：调用方机器上 `my-pi.sh --version` 正常，换机后报 `./my-pi.sh: line 7: dirname: command not found` / `line 16: mkdir: command not found`；对照 `bash -c 'uname -s'` 与 `bash -lc 'uname -s'` 后的 `command -v dirname`；`PATH` 里出现 `/d/...`、`/c/Users/...` 这类宿主路径即为泄漏

**含确切语法的解法**
**已硬化为 `scripts/run-my-pi.ps1` 的唯一调用姿势**：`bash -c`（非登录）+ **显式 PATH** 指向便携工具链的 `usr/bin` `mingw64/bin` `cmd` 与 node 目录；实测 `env -i` 下完全零外部依赖通过；详见 `docs/operations/BUILD-PORTABILITY.md` §4.3
