# 失败模式：**在 exFAT 卷上装依赖 ⇒ npm 报内部错误而非「不支持符号链接」**

**来源**：`docs/BUG-REPLAYS.md` 第 28 条（使用层面故障台账，代码检查全绿但用起来才炸）。

**是什么**
**在 exFAT 卷上装依赖 ⇒ npm 报内部错误而非「不支持符号链接」**

**根因（WHY）**
U 盘（exFAT）无法创建符号链接（Windows junction 亦被拒），而 npm workspaces 必须把工作区包符号链接进 `node_modules`（根 `workspaces:["custom"]`、`vendor/pi` 的 `packages/*`）⇒ 报 `Cannot read properties of null (reading 'edgesOut')`（arborist 内部错误），**完全看不出真实原因**。与 my-pi 自身理念冲突：`portable/` 本就禁止符号链接（`check-isolation.sh` 检查 1）

**确切命令序列**（复现/回归都靠它）
```bash
`bash -c '. scripts/lib-vendor.sh; preflight_symlinks "$PWD"; echo exit=$?'`（NTFS→0；exFAT→1 并打印原因与两条出路）；端到端：在 exFAT 上 `bash scripts/build.sh` 应在安装前即退出
```

**怎么发现它（指纹）**
同一个 `package.json`：NTFS 安装成功、exFAT 崩溃；`cmd /c 'mklink /D ...'` 回 `The device does not support symbolic links.`，`mklink /J` 回 `Local NTFS volumes are required`

**含确切语法的解法**
**已硬化**：`scripts/lib-vendor.sh` 新增 `preflight_symlinks`，`build.sh` 第 1b 步在**安装前**调用（根依赖与 vendor 构建都跳过时免检）；详见 `docs/operations/BUILD-PORTABILITY.md` §2
