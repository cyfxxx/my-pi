# 失败模式：**"取走即销毁"的共享状态被多个订阅者消费 ⇒ 只有第一个拿到，其余静默拿空**（DSH 换基座时抓到的真事故）

**来源**：`docs/BUG-REPLAYS.md` 第 40 条（使用层面故障台账，代码检查全绿但用起来才炸）。

**是什么**
**"取走即销毁"的共享状态被多个订阅者消费 ⇒ 只有第一个拿到，其余静默拿空**（DSH 换基座时抓到的真事故）

**根因（WHY）**
`turn_end` 这类 pi 事件会被**多个特性**注册（本仓 3 个），而适配层是"每个 pi 事件注册 ⇒ 一条独立订阅"⇒ **一条** DSH `turn/end` 触发**多条**桥接。回合用量累积器对外只提供 `take()`（取走即清桶），于是**只有第一条**桥接拿到用量，其余全部 `undefined` —— 而恰好需要它的 `recordUsage`（token 记账）**不在第一条** ⇒ 用量永久丢失，且**没有任何报错**：处理器正常返回、字段只是"恰好为空"。同类征兆是"某功能看起来接上了却永远没数据"

**确切命令序列**（复现/回归都靠它）
```bash
`bash -c 'MY_PI_HOST_SMOKE=1 MY_PI_DSH_TRACE_EVENTS=1 PI_USAGE_DIAG_FILE=/tmp/x.jsonl MY_PI_HOST_PROMPT="回答两个字：收到" bash scripts/dsh-host-smoke.sh; cat /tmp/x.jsonl'`（修前无该文件；修后写出 `{"input":213,"cacheRead":10368,"output":2,"total":10583}`）；单测：`npx vitest run custom/adapters/dsh/__tests__/usage-accumulator.test.ts`；真包探针：`bash scripts/dsh-spike.sh` 的 **A20**（真实 `SessionStore` + 兄弟子 ctx + 注册**两条** `turn_end`）
```

**怎么发现它（指纹）**
真 Host 打开 `MY_PI_DSH_TRACE_EVENTS=1` 一眼可见：`用量补丁=yes(calls=1)` 之后紧跟着**两条** `用量补丁=no`；而 `portable/memory/context/.usage-diag.jsonl` 的最后一笔真实记账比该次 Host 跑**早 1.66 天**（行数前后都是 1536，即一条都没写）——**反向证据（"应该写却没写"）比"跑通了"更能定位**。单测/探针：注册 2~3 个 `turn_end` 处理器，断言**每个**都拿到同一份用量

**含确切语法的解法**
**已修（2026-10-18，分支 `feat/base-switch-dsh`）**：`custom/adapters/dsh/usage-accumulator.ts` 对外只给 **`read`（只读不销毁）**，桶靠 LRU（32）与 `drop` 回收；并顺带修掉"只按回合号分桶"⇒ 不同会话的回合 1 会串账（改为**会话 id + 回合号**）。守门：单测 **112 项**（含多订阅者、跨会话不串账、无数据不合成、LRU 淘汰等反向探针）+ spike **A20**；真 Host 复验：三条桥接全部 `用量补丁=yes` 且**未被改动的特性**真的落盘 ✓
